# Phase 1 — MSW Demo Mode + Login Upgrade

> Sprint: 2026-08-19 · Status: ✅ done in ~25 min
> Theme: the app runs and demos WITHOUT the decommissioned backend.

## The problem this solves
The original backend (port 8003) is long dead → login was a dead relic. Options were: rebuild a backend (no time, no value) or **mock at the network boundary** with MSW. MSW intercepts requests via a service worker — the real axios client, real interceptors, real services all run; only the server is fake.

**The senior line:** "Same handlers run the live demo AND the Vitest suite — one mock layer, two uses."

## Files
| File | Role |
|---|---|
| `src/mocks/handlers.ts` | REST handlers: login, register, detail, revoke, verify-email, health. Response envelope mirrors `types/Auth.ts` (`data/status/error`). |
| `src/mocks/browser.ts` | `setupWorker(...handlers)` — dev/demo mode |
| `src/mocks/server.ts` | `setupServer(...handlers)` — Vitest (imported in test setup) |
| `src/main.tsx` | Async boot: `RTCS_DEMO !== 'false'` → dynamic-import worker → then render |
| `public/mockServiceWorker.js` | Generated by `npx msw init public/ --save` |

**Demo credentials:** `demo` / `password` (hint shown on the login card).

## Key mechanics
1. **Handler contract = the API's shape.** `ok(data)` → `{data, status: "SUCCESS", error: null}`; `fail(...)` → envelope + real HTTP status (401 wrong creds, 409 username taken). Wrong creds return HTTP 401 *with a body* — matching how the real API behaved (envelope, not bare status).
2. **Auth on `/auth/detail` is enforced in the mock too** — Bearer token checked, so the ProtectedRoute → dashboard flow exercises the real interceptor path.
3. **Async boot in main.tsx**: `enableDemoMode().finally(render)` — MSW must be ready before the first request fires. Dynamic import keeps MSW out of the bundle when demo is off.

## Login form upgrade (the form is now a complete snippet)
- Inline validation: field-level errors, submit blocked, errors clear on typing
- `aria-invalid` + `aria-describedby` on inputs, `role="alert"` on the form error
- `aria-busy` on the submit button while loading
- Show/hide password toggle (`aria-pressed`, labeled "Show secret" — see pitfall #2)
- Full state machine: idle → submitting → success/error

## Pitfalls hit (and what they taught)
1. **Toggle aria-label collided with test queries.** `aria-label="Show password"` made `getByLabelText(/password/i)` and `getByRole('button', {name: /password/i})` ambiguous → "found multiple elements". Renamed to "Show secret". Lesson: **accessible names are an API** — tests and screen readers share them, choose names that don't collide.
2. **`npm run dev` opens the browser automatically** (`open: true` in vite config) — fine locally, just noise when driving headless.
